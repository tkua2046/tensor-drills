### Deferred coverage

A standalone task for allocating an arbitrary requested shape and dtype is deferred in both tracks. `indexed-sum` assesses output allocation; `convert-dtype` assesses casting. These tasks do not establish general shape allocation. Revisit a dedicated drill if learner attempts show that allocating independently of an existing input remains a gap.

## Shared authoring briefs

Use the same brief when both libraries teach the same outcome. Supply each drill with its own starter, inputs, fixtures, and checks. Assume basic Python and the ability to read the labeled axes in the prompt. A dash indicates that the scope and task type are open.

**Milestone 4 contracts.** The pending Milestone 4 briefs below use CPU arrays or tensors; PyTorch inputs do not require gradients. Use native operations without Python element or row loops. Preserve input values, shape and dtype during the call. Layout and selection inputs are writable int64 data with Boolean masks; calculation inputs are finite float64 values of magnitude at most 16. Bound independent shape parameters, such as B, T, H and D, to 1–8; allow zero where a brief says so, and let a more specific bound take precedence. Derived dimensions and output counts, such as H*D, height*width and the number of selected elements, follow their formulas and are not separately capped at 8. Calculation outputs preserve float64, with relative tolerance `1e-12` and absolute tolerance `1e-10`. Put these assumptions and any graded operation or storage requirement in the learner prompt. A brief that does not promise sharing or contiguity accepts equivalent implementations with different storage choices. These defaults do not change completed drills.

For each planned drill, record the corresponding capability prerequisites in its metadata when authoring it. Axis insertion is practiced in `axis-layout`, Boolean conditions in the bundled `build-mask`, and reductions and shared contraction in Milestones 1–2. Delivery dependencies belong in the milestone tables above. Follow the existing [brief review](DRILL_AUTHORING.md#review-the-brief) and [verification recipe](DRILL_AUTHORING.md#verify-from-a-fresh-workspace); the evidence below specifies cases to prepare, not checks already run.
