### Deferred coverage

A standalone task for allocating an arbitrary requested shape and dtype is deferred in both tracks. `indexed-sum` assesses output allocation; `convert-dtype` assesses casting. These tasks do not establish general shape allocation. Revisit a dedicated drill if learner attempts show that allocating independently of an existing input remains a gap.

## Shared authoring briefs

Use the same brief when both libraries teach the same outcome. Supply each drill with its own starter, inputs, fixtures, and checks. Assume basic Python and the ability to read the labeled axes in the prompt. A dash indicates that the scope and task type are open.

**Milestone 4 contracts.** The Milestone 4 briefs below use CPU arrays or tensors; PyTorch inputs do not require gradients. Use native operations without Python element or row loops. Preserve input values, shape and dtype during the call. Layout and selection inputs are writable int64 data with Boolean masks; calculation inputs are finite float64 values of magnitude at most 16. Bound independent shape parameters, such as B, T, H and D, to 1–8; allow zero where a brief says so, and let a more specific bound take precedence. Derived dimensions and output counts, such as H*D, height*width and the number of selected elements, follow their formulas and are not separately capped at 8. Calculation outputs preserve float64, with relative tolerance `1e-12` and absolute tolerance `1e-10`; explicitly exact special-case results take precedence. Put these assumptions and any graded operation or storage requirement in the learner prompt. A brief that does not promise sharing or contiguity accepts equivalent implementations with different storage choices. These defaults do not change completed drills.

For each planned drill, record the corresponding capability prerequisites in its metadata when authoring it. Axis insertion is practiced in `axis-layout`, Boolean conditions in the bundled `build-mask`, and reductions and shared contraction in Milestones 1–2. Delivery dependencies belong in the milestone tables above. Follow the existing [brief review](DRILL_AUTHORING.md#review-the-brief) and [verification recipe](DRILL_AUTHORING.md#verify-from-a-fresh-workspace); the evidence below specifies cases to prepare, not checks already run.

## NumPy authoring briefs

**Milestone 6 contracts.** Use NumPy alone. Unless a brief overrides them, numeric results are float64 and finite input arrays have magnitude at most 16, independent shape parameters are 1–8, and numeric tolerances are relative and absolute `1e-10`. A brief can permit zero or another bound; derived dimensions follow their formulas. Discrete outputs use native integer or Boolean arrays. Preserve inputs and emit no warnings. Exact zero/infinity, ownership and discrete constraints override approximate comparisons. Use native vectorized operations; streaming callers may iterate chunks, but updates must not loop over individual values. Memory and mechanism requirements also need code evidence. These contracts are separate from Milestone 5.

For the pending Milestone 5 briefs, use NumPy alone, native vectorized operations, and finite float64 numeric data of magnitude at most 16 unless a brief overrides this. Independent shape parameters are 1–8; a brief may permit zero or specify another bound. Derived dimensions and selected counts follow their formulas. Preserve input values, shapes and dtypes. No Python loops over elements, rows or groups; `nearest-neighbors` permits a loop over reference blocks. Float64 results use relative and absolute tolerances `1e-10`; discrete outputs use native integer arrays or Boolean masks. Exact zeros, counts, indices and tie rules take precedence. Calls must emit no warnings. State each applicable contract in the learner prompt. These defaults do not change completed drills.

## PyTorch authoring briefs

**Milestone 6 contracts.** Use PyTorch alone on CPU with float64 numeric inputs/results and int64 indices. Unless overridden, numeric input magnitudes are at most 4 and independent dimensions are 1–4; zero extents need explicit permission. Preserve input data, shapes and tracking state. Each brief separately states whether input gradients start empty and whether the function performs backward or updates a model; Milestone 5 gradient-buffer preservation is not inherited. Floating outputs/gradients use relative and absolute tolerances `1e-10`; exact zeros and discrete/state invariants take precedence. Use native vectorized tensor operations; `microbatch-step` permits iteration over supplied microbatches. First-order derivatives are sufficient; higher-order differentiation is outside these drills.

Pending Milestone 5 tensor drills use PyTorch alone on CPU. Unless overridden, numeric inputs are finite float64 with magnitude at most 16, index data is int64, and independent shape parameters are 1–8; derived extents follow their formulas and zero sizes are allowed only where stated. Preserve caller data, shapes and dtypes and use vectorized native operations rather than element, row or group loops. Differentiable briefs supply trainable leaves with no incoming gradient: the function preserves their tracking state and gradient buffers, and returns outputs connected to them. Verifiers apply finite nonuniform upstream gradients of magnitude at most 16 after return. Compare floating outputs/gradients with relative and absolute tolerances `1e-10`; explicitly exact zeros and discrete results take precedence. These defaults do not change completed drills.
